# Совместимость с другими серверами и клиентами

Проверки чужим кодом: эталонный набор тестов IMAP, миграция из Dovecot с побайтовой сверкой и настоящие клиенты. Всё запускается в Docker против работающего mailstore на `:1143`. На машину ничего не ставится, версии образов и тестов закреплены.

## Результаты (26.11.2026)

| Проверка | Что делает | Итог |
|---|---|---|
| Dovecot imaptest, скриптовые тесты | 74 группы тестов на соответствие RFC 3501 и расширениям | **0 ошибок** в 35 группах (460 команд базового протокола, 26 команд расширений); 39 групп пропущены, они требуют расширений, которых мы не объявляем |
| Dovecot imaptest, стресс | 10 клиентов, 60 с, случайные команды со сверкой состояния папки | **0 ошибок**, ~1 350 команд/с |
| Миграция из Dovecot 2.4.5 через imapsync 2.326 | 375 писем (корпус imaptest + 200 сгенерированных MIME-деревьев) в 4 папках, с флагами и ключевыми словами | перенесено всё, повторный прогон переносит 0; сверка с Dovecot по каждому письму: байты, FLAGS, INTERNALDATE, RFC822.SIZE, ENVELOPE, BODYSTRUCTURE — **0 расхождений** |
| mbsync (isync 1.5.1) | двусторонняя синхронизация в Maildir | проходит |
| OfflineIMAP 8.0.0 | то же | проходит |
| imapflow 2.11.0 (Node) | типичный сервис: LIST, FETCH ENVELOPE/BODYSTRUCTURE, скачивание вложения по номеру части, SEARCH, флаги, IDLE, CREATE/RENAME/DELETE, MOVE, STATUS | проходит |

Сценарий синхронизации одинаковый для mbsync и OfflineIMAP:
1. На сервере письма в двух папках, первая синхронизация.
2. Локально: прочитать письмо, удалить письмо, создать папку с письмом; синхронизация.
3. На сервере: новое письмо и `\Flagged`; синхронизация.
4. Повторная синхронизация без изменений.

После каждого шага состояние сверяется с обеих сторон.

### Что нашли и исправили

- **CREATE / DELETE / RENAME не было.** На них падали почти все тесты imaptest.
  - Теперь CREATE создаёт недостающих родителей.
  - RENAME переносит поддерево, UID и UIDVALIDITY сохраняются.
  - DELETE не удаляет папку с детьми (`[HASCHILDREN]`, как в Dovecot).
  - Сессии с открытой папкой узнают о переименовании сразу, а при удалении получают `BYE`.
- **UIDVALIDITY повторялся.** Он брался из времени в секундах, и пересозданная за ту же секунду папка получала прежний UIDVALIDITY. Теперь он берётся из последовательности Postgres.
- **`\Recent` не было:** RECENT всегда был 0, SEARCH NEW/RECENT ничего не находил. Теперь работает по RFC 3501. Состояние живёт в памяти актора и после его рестарта начинается заново: `\Recent` справочный, а в IMAP4rev2 его убрали.
- **Ключевые слова не попадали в `* FLAGS`.** imaptest считает это ошибкой: клиент не должен увидеть в FETCH флаг, которого не было в FLAGS. Теперь SELECT перечисляет используемые в папке ключевые слова, а новое ключевое слово объявляется до первого FETCH с ним.
- **SUBSCRIBE ничего не делал**, LSUB показывал все папки. Теперь подписка хранится, а LSUB с `%` показывает неподписанного родителя подписанной папки как `\Noselect`.
- **ENVELOPE:**
  - группы адресов (`team: a@x, b@y;`);
  - имя в комментарии (`user@host (Real Name)`);
  - комментарии внутри адреса;
  - маршруты `<@route:user@host>`;
  - пустой `Sender:` подменяется на From;
  - `MISSING_DOMAIN` вместо пустого хоста;
  - пробелы схлопываются, как в Dovecot.
- **SEARCH SENTBEFORE/SENTON/SENTSINCE** сравнивали дату доставки, а не заголовок `Date:`. FROM/TO/CC/BCC не находили адрес, спрятанный за комментарием.
- **BODYSTRUCTURE, расхождения с Dovecot:**
  - число строк считается как число LF;
  - имена параметров сохраняют регистр;
  - значения по RFC 2231 (`filename*=utf-8''%D1%84...`) раскодируются в UTF-8.

### Что не проверено

- **Почтовые программы с GUI** (Thunderbird, Apple Mail, Outlook, почта iOS и Android): их нужно проверить вручную.
- **Расширения, которых мы не объявляем, поэтому клиенты их не используют:**
  - CONDSTORE/QRESYNC: Thunderbird и Apple Mail ими ускоряют синхронизацию, но работают и без них;
  - ESEARCH, SORT, THREAD (нужны веб-клиентам вроде Roundcube);
  - BINARY, LIST-EXTENDED, MULTIAPPEND, CATENATE, NOTIFY.

## Запуск

```bash
mix run --no-halt &                          # mailstore на :1143
mix run --no-start compat/setup_accounts.exs # аккаунты *@compat.test, пароль swordfish

compat/imaptest.sh        # imaptest: скриптовые тесты и стресс (скачивает тесты в compat/.cache)
compat/migration.sh       # Dovecot -> imapsync -> mailstore, сверка писем (нужен корпус из imaptest.sh)
compat/clients.sh         # mbsync, OfflineIMAP, imapflow
```

- **Таймауты Docker CLI.** Если `docker pull` или `docker build` висят на помощнике учётных данных (связка ключей macOS), задайте `DOCKER_CONFIG` с конфигом без `credsStore`.
- **Почему стресс идёт на постоянных соединениях.** Со стандартным LOGOUT после каждого цикла imaptest открывает около 200 соединений в секунду, и через несколько секунд проброс портов Docker Desktop перестаёт принимать новые. Сервер при этом в порядке. Поэтому стресс запускается с `logout=0`.
- **imapsync опознаёт письма по заголовкам** и пропускает письма без Message-ID и дубли. В корпусе imaptest есть и то и другое, поэтому засев добавляет к каждому письму уникальный `X-Compat-Seq`, а imapsync опознаёт письма по нему.
- **OfflineIMAP и флаг `T`.** Для него это только `\Deleted` без EXPUNGE, а удалением считается исчезновение файла. Сценарий удаляет файл.

Файлы:
- **`clients/Dockerfile`** — образ с mbsync, OfflineIMAP и imapflow;
- **`clients/imapcmp.py`** — засев сервера, очистка ящика и сверка двух серверов;
- **`clients/gen_mime.py`** — генератор MIME-корпуса;
- **`clients/sync_clients.py`** — сценарий синхронизации;
- **`clients/imapflow_test.js`** — сценарий сервиса.
